### 內容說明

**`.node-version`**
```text
24
```
- 就一行字。fnm 進到資料夾時會讀這個檔案，自動切換 Node 版本。
- **前端類比**：就像 `package.json` 的 `engines` 欄位，但這個會真的幫你切換，不只是提醒。
- 很多工具都認得這個檔案，例如 CI 的 `actions/setup-node`，之後 F5 會用到。

**`.python-version`**
```text
3.12
```
- `uv python pin 3.12` 產生的檔案。uv 執行 Python 時，會用這個版本。
- 為什麼不用你電腦上的 Python 3.14？TensorFlow、onnxruntime 這類機器學習套件，通常要等幾個月才會支援新的 Python 版本，**3.12 最穩定**。

**`.mcp.json`**
```json
{ "mcpServers": { "context7": { "type": "http", "url": "https://mcp.context7.com/mcp" } } }
```
- **MCP（Model Context Protocol）**：讓 Claude 可以呼叫外部工具的標準介面。
- **前端類比**：像是幫 Claude 裝了一個「查文件 API」的 SDK。
- 放在 repo 裡是**專案層級**的設定：只要 clone 這個專案，就會有同一套工具。
- 之後我寫 NestJS 或 Drizzle 的程式碼時，會先用 Context7 查你安裝版本的文件，避免用到舊的 API。

**`~/.zshrc` 新增的內容**
```sh
eval "$(fnm env --use-on-cd --shell zsh)"
```
- `fnm env` 會輸出一段設定 PATH 的 shell 指令，`eval` 則負責執行它。
- `--use-on-cd`：每次 `cd` 切換目錄時，檢查有沒有 `.node-version`。
- **前端類比**：就像註冊了一個 `onRouteChange` 事件，換頁時自動載入對應的設定。

**工具說明**

| 工具 | 是什麼 | 前端類比 |
|---|---|---|
| fnm | Node 版本管理 | nvm 的快速版，用 Rust 寫的 |
| corepack | Node 內建工具，負責管理 pnpm 或 yarn 的版本 | 讓每個專案固定用同一版的 pnpm |
| uv | Python 的版本管理、套件管理、虛擬環境，三合一 | pyenv + pip + venv 的組合，大約等於 Python 界的 pnpm |
| 虛擬環境（venv） | 每個 Python 專案都有一個獨立的套件資料夾 | 就是 Python 的 `node_modules` |

### 這次學到的重點
1. **版本要跟著專案走，而不是跟著電腦走**：`.node-version`、`.python-version` 都會 commit 進 repo，不管是你、CI 還是 Docker，都會用同一個版本。
2. **uv 對 Python 的角色，就像 pnpm 對 Node**：一個工具就能管理版本和套件，並且有 lock 檔。
3. **機器學習專案不要用最新版的 Python**：先確認你要用的套件支援哪些版本。
4. **conda 和 uv 盡量不要混用**：兩個都會搶著提供 `python` 指令。

### 待辦 / 風險 / 需要你決定的事
1. **核准 Context7**：專案層級的 MCP 伺服器，第一次使用前需要你核准。下次開 Claude Code session 時，應該會跳出核准提示，按允許即可。
2. **fnm 的小限制**：在同一個終端機分頁裡，進入專案後再 `cd` 到其他地方，Node **仍然會是 24**，因為 fnm 只會在找到 `.node-version` 時切換版本。其他專案如果需要 Node 26，開新的分頁就好。
3. **conda 沒有被移除**：還是可以用 `conda activate base` 手動啟用。如果想回到原本的設定，執行 `conda config --set auto_activate true`。
