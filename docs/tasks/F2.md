## 0. 一句話總結

**一個指令 `docker compose up -d --wait`，約 6 秒就能在本機啟動整個專案的基礎設施**：

| 服務 | 用途 |
|---|---|
| PostgreSQL 18 + PostGIS + pgvector | 業務資料、GPS 距離查詢、向量相似度 |
| Redis 8 | BullMQ 佇列 |
| SeaweedFS | S3 相容的照片儲存 |

三個服務都有健康檢查、資料在重啟後仍會保留，而且只有你的 Mac 連得到。

## 1. 最終架構

```text
你的 Mac（127.0.0.1）                          Docker Desktop 內的 Linux VM（arm64）
───────────────────────                        ─────────────────────────────────────────
                                               網路：heartlink_default
localhost:5433  ──port mapping──▶  postgres:5432     [heartlink/postgres:18-postgis3-pgvector0.8.6]
                                                      └─ volume: heartlink_postgres-data → /var/lib/postgresql
localhost:6380  ──port mapping──▶  redis:6379        [redis:8.8.2-alpine]
                                                      └─ volume: heartlink_redis-data → /data
localhost:8333  ──port mapping──▶  seaweedfs:8333    [chrislusf/seaweedfs:4.46]  S3 API
localhost:23646 ──port mapping──▶  seaweedfs:23646   管理介面
                                                      └─ volume: heartlink_seaweedfs-data → /data

之後（F3）的 api、ai 容器在同一個網路裡，會直接用 postgres:5432、redis:6379、seaweedfs:8333 連線。
```

| 7 | 🟢 | `services:` | 以下定義每個容器 |
| **8–26** | 🟢 | **`postgres` 服務** | 主資料庫，同時支援 GPS 查詢和向量查詢（D03） |

| 部分 | 意思 |

| `FROM` | 以這個映像為基礎往上加東西。**前端類比**：像 `extends` 一個現成的 tsconfig |
| `pgvector/pgvector` | pgvector 官方映像，它本身是以官方 `postgres` 映像為基礎 |
| `0.8.6` | pgvector 的版本 |
| `pg18` | PostgreSQL 18 |
| `trixie` | 底層是 Debian 13（代號 trixie） |

```dockerfile
ARG POSTGIS_MAJOR=3
RUN apt-get update \
  && apt-get install -y --no-install-recommends "postgresql-${PG_MAJOR}-postgis-${POSTGIS_MAJOR}" \
  && rm -rf /var/lib/apt/lists/*
```
| 片段 | 作用 | 為什麼這樣寫 |
|---|---|---|
| `ARG POSTGIS_MAJOR=3` | 建置時的變數 | 之後要升級 PostGIS 時，只改一個地方 |
| `apt-get update` | 下載 Debian 的套件清單 | apt 是 Debian 的套件管理工具，**大約等於 Linux 版的 npm** |
| `apt-get install -y` | 安裝套件，`-y` 代表自動回答 yes | 建置過程不能停下來等人輸入 |
| `--no-install-recommends` | 不安裝「推薦但非必要」的套件 | 讓映像小一點 |
| `${PG_MAJOR}` | 基礎映像已經設定好的環境變數，值是 `18` | 不用寫死版本，PostgreSQL 版本會跟著基礎映像走 |
| `rm -rf /var/lib/apt/lists/*` | 刪除剛下載的套件清單 | 這些檔案之後用不到，刪掉可以減少映像大小 |
| `&&` 串成一個 `RUN` | 三個動作只產生一層 | 如果分成三個 RUN，第一層的清單檔案會永遠留在映像裡 |

```dockerfile
COPY init/ /docker-entrypoint-initdb.d/
```
- 官方 postgres 映像有一個約定：**當資料目錄是空的**（第一次啟動）時，會自動執行 `/docker-entrypoint-initdb.d/` 裡的 `.sql` 和 `.sh` 檔案。
- **前端類比**：很像只會在第一次安裝時執行的 `postinstall`。

### 4.2 `infrastructure/postgres/init/01-extensions.sql`

```sql
CREATE EXTENSION IF NOT EXISTS postgis;
CREATE EXTENSION IF NOT EXISTS vector;
```
| 名詞 | 解釋 |
|---|---|
| **extension（擴充套件）** | PostgreSQL 的外掛，裝了才有新的資料型別和函式。**前端類比**：安裝 npm 套件之後，還要 `import` 才能使用 |
| **postgis** | 地理資訊擴充套件，提供 `geography` 型別和 `ST_DWithin`、`ST_Distance` 這類函式，用來做「公里半徑內的候選人」查詢 |
| **vector** | pgvector 擴充套件，提供 `vector(N)` 型別和 `<=>`（cosine 距離）運算子，用來比較人臉、偏好、語意向量 |
| `IF NOT EXISTS` | 已經啟用就略過，重複執行也不會出錯（idempotent，冪等） |
| 檔名前綴 `01-` | 多個 init 檔案會依檔名順序執行 |

**為什麼這裡不建立資料表？** 依照 D24，資料表結構一律交給 Drizzle migration 管理。init 腳本只會執行一次，之後改了也不會再執行，不適合用來管理會持續變動的東西。

### 4.4 `docker-compose.yml`：postgres 服務

| 設定 | 值 | 解釋 |
|---|---|---|
| `build` | `./infrastructure/postgres` | 用這個資料夾裡的 Dockerfile 自己建置映像 |
| `image` | `heartlink/postgres:18-postgis3-pgvector0.8.6` | 建置出來的映像名稱。**把版本寫進標籤**，一看就知道裡面裝了什麼 |
| `restart` | `unless-stopped` | 容器當掉或 Docker 重啟時，會自動重新啟動；你手動停止時則不會 |
| `environment.POSTGRES_USER` 等 | `${POSTGRES_USER:?…}` | 從 `.env` 讀取；**沒有設定就直接報錯**。官方映像第一次初始化時，會用這三個值建立使用者和資料庫 |
| `ports` | `127.0.0.1:${POSTGRES_PORT:-5433}:5432` | Mac 的 5433 → 容器的 5432；只綁定本機 |

| `interval` / `timeout` / `retries` | 5 秒 / 3 秒 / 10 次 | 每 5 秒檢查一次，每次最多等 3 秒，連續失敗 10 次就標記為 unhealthy |
| `start_period` | 10 秒 | 啟動後的前 10 秒，檢查失敗不列入計算（初始化需要時間） |

### 4.5 `docker-compose.yml`：redis 服務

| 設定 | 值 | 解釋 |
|---|---|---|
| `image` | `redis:8.8.2-alpine` | Redis 官方映像，版本寫到確切的 patch；alpine 版比較小 |
| `command` | `redis-server …` | 覆寫容器的啟動指令，加上我們需要的參數 |
| `--maxmemory-policy noeviction` | — | **BullMQ 的硬性要求**：記憶體滿了就讓寫入失敗，而不是偷偷刪掉舊的資料。否則佇列裡的工作可能憑空消失 |
| `--appendonly yes` | — | **AOF 持久化**：每次寫入都記錄到檔案，重啟後可以還原。沒有開的話，Redis 的資料只在記憶體裡，一重啟就沒了 |
| `--requirepass ${REDIS_PASSWORD}` | — | 沒有密碼的連線會被拒絕 |
| `environment.REDISCLI_AUTH` | Redis 密碼 | `redis-cli` 會自動讀取這個變數，所以健康檢查不必把密碼寫在指令上 |
| `volumes` | `redis-data:/data` | AOF 檔案存放的位置 |
| `healthcheck` | `redis-cli ping` | 正常時會回 `PONG` |

**名詞解釋：Redis** 是一個把資料放在記憶體裡的鍵值資料庫，非常快。**前端類比**：像一個所有程式共用的超快 `Map`。BullMQ 用它來存放「待處理的工作清單」。

### 4.6 `docker-compose.yml`：seaweedfs 服務

| 設定 | 值 | 解釋 |
|---|---|---|
| `image` | `chrislusf/seaweedfs:4.46` | SeaweedFS 官方映像。4.47 是 3 天前才發布的，所以選了 9 天前的 4.46，理由跟 D27 相同 |
| `mini` | — | 單機全功能模式：一個程序包含 master、volume、filer、S3、管理介面，**專門為開發環境設計** |
| `-dir=/data` | — | 資料存放在容器的 `/data`，也就是 volume 掛載的位置 |
| `-bucket=photos` | — | 啟動時如果 `photos` bucket 不存在，就自動建立。**bucket** 大約等於一個最上層的資料夾 |
| `-admin.user` / `-admin.password` | — | 管理介面的帳號密碼；沒設定密碼的話，管理介面**不需要登入**，所以一定要設 |
| `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` | 從 `.env` 的 S3 變數而來 | SeaweedFS 會把這組金鑰建立成 S3 的管理者帳號。之後程式用 AWS SDK 連線時，就用這組金鑰 |
| `ports` | 8333、23646 | S3 API、管理介面 |
| `healthcheck` | `wget … /healthz` | 實驗確認這個網址會回 200 |
| `retries: 20`、`start_period: 15s` | — | SeaweedFS 要啟動好幾個內部元件，所以給它多一點時間 |

**名詞解釋**
- **物件儲存 / S3**：存放檔案（例如照片）的服務，用 HTTP API 上傳、下載。AWS S3 是業界標準，很多工具都相容它的 API。
- **前端類比**：像一個只能透過 `fetch` 存取的雲端硬碟，每個檔案都有一個「鍵」（例如 `users/123/avatar.jpg`）。
- **為什麼不把照片存在資料庫？** 資料庫適合存結構化資料，大型檔案放在物件儲存比較便宜、也比較快。資料庫只記錄檔案的鍵（`user_photos.storage_key`）。

## 9. 這次學到的重點

1. **image 是藍圖，container 是實體，volume 是會保留下來的資料**。容器可以隨時刪掉重建，資料放在 volume 就不會消失。
2. **健康檢查 ≠ 正在執行**：服務要「可以用」才算準備好。`--wait` 和 `depends_on: service_healthy` 都靠健康檢查來判斷。
3. **port mapping 的左邊是你的 Mac，右邊是容器**；容器之間則用「服務名稱 + 容器裡的 port」連線。
4. **init 腳本只會執行一次**：只放不會變動的設定（例如啟用擴充套件），資料表交給 migration。
5. **選映像先檢查三件事**：有沒有 arm64 版本、還有沒有人維護、標籤要寫到確切的版本。
